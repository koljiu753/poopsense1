# PoopSense Web / PWA

React + TypeScript + Vite 前端，围绕家庭成员的“记录 → 报告 → 回应 → 行动回看与趋势”组织体验。当前使用亮粉、明黄、蓝、奶油白和黑色品牌，角色与说话气泡贯穿首页及报告。

## 页面与主要操作

| 页面 | 当前行为 |
| --- | --- |
| 首页 | 选择成员，查看最近一次记录及时间，打开该条报告；近期足迹可打开对应旧记录。已保存回应随记录重新读取。 |
| 报告 | 先展示可靠观察、一项优先建议和回应，其他建议与依据按需展开。紧急/信息不足说明完整保留；回应保存成功才显示已记下。 |
| 健康 | 默认进入记录，分为记录、行动、趋势。行动先显示后续观察和感受入口，再连接源报告；趋势支持 30/90 天与个人基线。 |
| 广场 | 角色场景、地图与公开动态；写动态或点相应地点打开当前屏幕的发布面板，每条发布都需明确确认。 |
| 我的 | 成员、设备、家庭查看权限、伙伴偏好及开发连接设置；低频内容按需展开，原始数据授权单独确认。 |

“准备试试”只表示采用意向。后续观察读取后端的可靠记录对照；前端不重新推导健康结论，也不将前后变化解释为建议的因果效果。

## 新记录与读取状态

当前成员的记录每 5 秒轮询。首次同步仅建立已有记录范围，不把历史记录当作新检测。

- 停留首页、报告或结果过场且没有待看队列时，新记录可进入角色过场和自动报告；减少动态效果设置下跳过过场。
- 停留健康、广场或“我的”时，新记录先进入页面内提醒，用户选择查看或稍后。普通提醒不抢输入焦点，安全提醒明确优先；队列防止普通新记录覆盖尚未查看的安全项。
- 记录与趋势独立读取。首次失败、刷新失败、读取中和无记录分别显示，并提供对应重试入口。
- 切换成员会清理旧范围的待看队列。旧查询与迟到模拟回调必须校验成员、请求状态及当前页面，不能强制打开旧结果。

## 导航、返回与草稿

`src/useAppNavigation.ts` 管理浏览器历史和 hash 地址，例如：

```text
#/home?member=m_001
#/health/records?member=m_001
#/health/trends?member=m_001&days=90
#/health/actions?member=m_001&source=<record-id>
#/report?member=m_001&record=<record-id>
#/chat?member=m_001
```

地址只携带页面定位用的标识，不包含报告正文、草稿或连接密钥；地址本身不授予访问权限。重新打开时先校验当前家庭的成员，再匹配该成员可查看的记录，缺失时显示读取/失败/不可用状态，不改为分析另一条记录。

浏览器返回、前进及页面内返回共用历史；报告来源、健康分区、趋势范围和可恢复的滚动位置随之还原。导航时聚焦页面标题，返回原入口时尝试恢复触发按钮焦点；相同页面重复点击不增加历史条目。

普通追问等待和完成后保留当前报告及已保存回应；可选运行详情读取失败也不能清空报告。新的记录分析仍清理旧报告，实际返回新报告时按新内容替换。

同一次打开应用期间，同一成员的广场草稿和“我的”未提交编辑可跨页保留。页面重新激活时读取服务端状态，已编辑字段不被迟到快照覆盖。换成员或家庭连接范围后重建状态，隔离旧草稿与许可；刷新后不承诺恢复未提交草稿。

## 发布面板与键盘

问答使用独立输入组件保留草稿，逐字输入不重新渲染完整报告与历史。手机输入框位于导航上方，并跟随可见区域与键盘调整；Enter 保留换行，使用发送按钮提交。回答支持安全渲染的段落、重点、列表和局部横滚表格；不执行模型返回的 HTML 或危险链接。长回答使用页面滚动，历史对话默认折叠并分批显示。

慢历史读取不再阻挡提问；正文到达后立即解锁追问，可选详情在后台读取。晚到的旧历史或详情不能覆盖新一轮问答。用户开始报告页提问后，未开始的自动报告不会折叠其回答或清除重试状态。

`src/ComposeDialog.tsx` 使用原生对话框：打开时聚焦正文，支持 Tab / Shift+Tab、Escape 和关闭按钮，关闭时恢复背景滚动与触发焦点。关闭后重开保留草稿；发布成功后清空正文及本条公开许可。

面板监听 `visualViewport` 与窗口变化，随可见高度和偏移调整，保留标题和关闭入口，正文独立滚动。已做可见区域缩小模拟，仍需手机真机软键盘验证。

## 传感事实到卡通

界面读取后端的 `visual_profile`，不从 Agent 文案猜测形象：

| 可靠形态 | 角色 |
| --- | --- |
| `normal / elongated` | 顺滑长条 |
| `hard / scattered` | 分散颗粒 |
| `loose / irregular` | 不规则形态 |
| `compact` | 紧实成团 |
| 不可靠、置信度不足或未定义 | 不确定形象，不展示具体传感标签 |

可靠形态的映射不代表疾病诊断。普通回应不能覆盖紧急提示或“本次无法可靠判断”。机械臂、VBot 和取水执行不属于当前前端流程。

## 启动与配置

先按 [根目录 README](../README.md) 安装并启动后端，再在本目录运行：

```powershell
npm ci
npm run dev
```

打开 `http://127.0.0.1:5173/`。默认 API 使用同源路径，Vite 将 `/api`、`/health` 和 `/ready` 代理到本机 `8000` 端口。可用服务端地址通过 `VITE_API_BASE` 或“我的”开发连接设置指定；模型密钥不得放进前端配置。

Windows 也可在项目根目录运行 `./start_demo.ps1 -LocalOnly`。需要同一 Wi-Fi 下的手机访问时，使用 `./start_demo.ps1` 输出的局域网地址，前端仍经同源代理访问后端；手机上的 `127.0.0.1` 指手机自身。

开发连接配置保存在当前标签页的 `sessionStorage`，属于演示/开发机制，不能替代正式登录。PWA 可缓存静态界面，健康 API 不作离线缓存。

## 部署结构

根目录 `vercel.json` 保留前后端 Services 一体部署。`frontend/vercel.json` 也支持单独发布新版界面，通过同域重写沿用现有公网演示后端；它不会连接本地电脑。两种配置都属于演示用途，不等于持久化生产环境。

正常 Git checkout 已包含品牌图片。仅源码上传时，构建前会从既有公开提交下载缺失图片并校验 SHA-256；资源声明位于 `frontend/scripts/public-assets.json`。

页面使用8张无损WebP，较对应PNG合计减少29.2%传输体积；可见像素和透明度已逐像素核验一致。原PNG保留，地图/设备图按需加载。首轮公网读取曾在图像慢载时超时，刷新后恢复，不以压缩宣称网络问题已全部消除。
