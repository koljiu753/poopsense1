# Reader：上传后自动卡通与 AI 演示解读

2026-09-22。本轮将已有卡通过场和 AI 演示解读接回完整流程。卡纸、橡皮泥记录只用于演示，不能生成真实健康报告。

## 打开哪个页面

打开 [Reader 硬件演示](https://poopsense-reader-0912.vercel.app/#/demo)，也可从 Reader 首页点击「打开硬件演示」。自有域名入口为 [poopsense.org 硬件演示](https://poopsense.org/#/demo)。

1. 首次先在「家庭连接设置」连接测试家庭，使用家庭查看密钥，API 地址留空。已有连接无需重新配置；家庭查看密钥与设备上传密钥分开使用。
2. 选定演示设备；家庭只有一个启用设备时自动选择。让页面留在前台。
3. 硬件队友用原采集/上传程序上传一次。页面约每 5 秒检查新记录，先显示本条颜色、形状卡通，再自动调用 DeepSeek 并显示保存的解读。正常流程不用复制记录 ID 或点击生成。

首次打开显示设备最新一条，若它尚未生成会自动生成；不追溯全部历史。当前标签页记住设备、游标与待处理记录 ID，刷新后先恢复未处理队列，再追新记录。连续多条按到达顺序展示；本条结束后停留约 2.2 秒再切下一条，可在「本轮已处理」回看最近 20 条。

切换到其他页面或浏览器后台会停止新读取和新生成；已经提交的服务端生成可能继续完成。返回后读取保存状态并追上新记录，不依赖常驻后台任务。不同域名需各自建立家庭连接，不通过 URL 传递密钥。

## 演示观测与健康结论分开

- 复用原过场布局和预置的四种形状卡通，按红、绿、蓝、黄观测着色，不等待模型画图。形状或颜色缺失时保留未知，不补猜。
- 页面明确显示模拟/硬件测试来源及手动采样；未认领记录不归属于当前成员，不自动认领。
- 原始相似度不是准确率，手动采样秒数不是如厕时长。气味等停用项保持未知。
- 解读由原 `demo-explanation` 服务根据同一条记录的保存事实调用 DeepSeek，复用权限、事实检查、去重、失败状态和持久化。原健康可靠性、`llm_status=not_applicable`、基线和趋势门控不改变。

## 断网、重传和失败

断网时保留已有展示，前台恢复后继续读取；生成结果不明时只查询状态，不自动重发。服务端已明确失败时保留「重试生成」，由用户显式重试。若生成请求未到达服务端，重新查询确认仍未生成后可以手动尝试，不循环提交。

重复上传原包复用同一记录；已完成解读从数据库恢复。按 ID 查找和手动生成保留为排查入口，不是日常测量步骤。

## 服务端变化

新增家庭鉴权只读接口 `GET /api/v1/households/{household_id}/devices/{device_id}/demo-sessions`。不传 `after_id` 时读取最新候选一条；传游标后按内部插入 ID 升序读取，`limit` 默认 20、范围 1–100，返回 `items/next_after_id/has_more`。过滤为手动采样且用途为 `simulated` 或 `hardware_test`，逐条核对成员权限，未认领记录仅管理角色可读。

同设备上传事务在分配记录 ID 前锁定设备绑定，直至原有整体提交；保证设备游标不会跳过晚提交记录，不阻挡其他设备。原上传 HTTP 地址、JSON 契约、回执、客户端与设备/家庭密钥保持不变，无数据库迁移。旧 Reader 联调包与 Exhibition 包保留。
