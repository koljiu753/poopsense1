# 2026-09-22 自有域名与记录查询体验

[poopsense.org](https://poopsense.org/) 现在绑定Reader项目，后续前端生产部署会更新该域名。原 [Reader入口](https://poopsense-reader-0912.vercel.app/) 同时保留，连接同一live-demo后端和Neon PostgreSQL测试库。

## 域名接入

用户在此前任务明确购买的是poopsense.org，本轮要求继续迭代并询问该域名能否使用。首次检查时HTTPS已可访问，但域名仅通过旧手工别名关联后端，未出现在后端项目的正式域名列表中；这会使只发布Reader的前端变化无法自动跟随。

已通过Vercel官方项目域名接口将poopsense.org登记到`poopsense-reader-0912`，返回verified=true，别名也确认指向Reader部署。CLI最初尝试从后端删除不存在的正式域名记录时404，未当作成功；随后按实际域名列表使用官方添加接口完成绑定。根域A记录、Spaceship名称服务器和其他域名未修改，无需重新购买域名。接口依据见[Vercel官方文档](https://vercel.com/docs/rest-api/projects/add-a-domain-to-a-project)。

使用不带www的地址；www.poopsense.org当前未配置DNS。首次在新域名查看独立测试家庭，需要在“我的→开发连接设置”重新输入家庭ID和家庭查看密钥，API地址留空。浏览器会话授权按域名隔离，记录没有迁移或重新上传，密钥不通过URL传递。

硬件队友已收到的Python上传工具继续使用固定Reader API地址，无需改动。此轮不变更数据契约、设备凭据、数据库、模型或worker设置，也没有更改Exhibition备用包。

## 记录查询修正

- 先按ID找到记录、再在同页认领，查询卡片现在收到认领成功通知后重新读取同条记录。归属仍取服务端结果，不由前端自行猜测；查另一条记录时，之前的认领通知不会把页面切回去。
- 刷新同一条记录时保留原始观测，明确提示当前仍为上次读取内容。网络失败时保留快照与重试按钮，不误称本次更新已完成。换ID、家庭授权失效、记录不存在或ID歧义时清除旧结果，避免错误地继续展示。
- 新查找和认领后刷新使旧请求失效；已经开始的旧响应不能覆盖新查询。保持已有品牌配色和窄屏布局，不调用模型重新解释硬件测试数据。

## 验证范围

绑定后，实际HTTPS分别从两个入口读取首页、JS/CSS、ready、已认领模拟记录的设备回执和家庭记录、OpenAPI，结果一致；数据库为postgresql/migrations。同一记录为上一轮的`reader_synthetic_f2ee7ca349474773`，仍属于`simulated`，不是新硬件采集证据。域名与查询测试不自动代表微信、Mac或ESP32/USB真机验收。

独立浏览器在poopsense.org从默认演示家庭进入“我的→开发连接设置”，通过真实保存按钮验证私有家庭授权，查询原记录并在整页刷新后再查成功。记录归属、原始观测与不足状态一致；50个实际GET200，另外2个切换时未结束未算成功；零业务写入、模拟响应、模型调用或捕获JS错误，验证后清除浏览器会话授权。第一次脚本错误假设默认家庭为空导致入口等待失败，原证据保留，按实际“我的”入口调整后通过。

本轮前端完整183项测试、TypeScript检查与生产构建通过。新增覆盖慢网保留DOM/折叠状态/键盘焦点、失败后重试、认领前旧读取失效、A/B查询竞态、授权拒绝清空、换家庭与卸载隔离，以及App实际认领成功/失败的通知接线。测试使用虚构fixture，不向模型或真实设备发送请求。
