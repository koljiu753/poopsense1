# Mobile chat responsiveness and readable replies

In the mobile chat, the composer could sit behind navigation, Markdown appeared as plain text, and sending stayed locked while optional run details loaded after an answer. This update keeps the composer above navigation and the on-screen keyboard, renders readable paragraphs and lists, and unlocks the next question as soon as the reply arrives.

Slow history loading no longer blocks a new question. Late history and run details cannot overwrite newer interaction state. Early questions on a report page retain their answer or retry state rather than being immediately folded into an automatic report. Drafts stay local to the composer, and historical messages render on demand.

Interactive calls to the official DeepSeek API explicitly disable thinking and use a bounded answer budget with concise mobile formatting. Truncated or empty answers fail explicitly; deterministic report fallback remains labeled. Background planning and weekly-report calls are unchanged. Permissions, safety checks, and audit behavior remain in place.

Validation: backend 116 tests passed; frontend tests and mobile browser verification are recorded in the final handoff. Keyboard tests cover visual viewport changes, layout viewport resizing, orientation changes, focus and draft preservation, and cleanup. Actual WeChat behavior and response latency must be checked separately from simulated keyboard tests.

This remains a demonstration with temporary storage. Deployment details will be added after the deployed application has been checked.
