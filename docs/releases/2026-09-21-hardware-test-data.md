# 2026-09-21 硬件测试数据与数据库准备

本轮面向测试/demo：设备上传可以来自实机试验，但不将其描述为正式用户健康数据或临床验证。云端持久化仍需部署账号完成数据库集成确认；当前网页的临时 SQLite 不能保证跨实例或重新部署后保留记录。

## 软件改动

- 上传新增可选 `data_kind`：`simulated`（模拟记录）、`hardware_test`（硬件上传的测试记录）、`unknown`（未标注）。未提供的新旧请求保持原哈希；明确分类参与哈希，同一记录不能靠重传偷偷改分类。
- 上传回执、待认领列表、成员记录返回分类；页面在原记录位置显示来源。`hardware_test` 不代表每个维度都是实采，更不代表测量可靠；质量及缺失值仍按原契约填写。
- 两个请求同时首次上传同一设备/记录时，在数据库唯一约束冲突后回滚并重新验证权限，同包复用、异包返回409；记录、观测、评估和事件仍一起提交。
- 页面可见时每5秒读取待认领记录，回到页面立即读取；不抢走聊天、草稿或焦点。认领期间旧响应失效，家庭/凭据切换不沿用旧列表，失败提示留在记录区。
- 新数据库迁移 `b92f17c03a64` 给旧记录标记 `unknown`，不猜测历史来源；重启不再覆盖演示成员昵称。PostgreSQL驱动加入部署依赖，连接池支持断开重连及受控连接数量。

## 一次性测试环境初始化

`backend/scripts/bootstrap_test_workspace.py` 仅接受显式demo模式与PostgreSQL地址。数据库必须先迁移到当前head；脚本不自动建表，不删除表，不覆盖已有不同绑定。完整相同配置重跑返回unchanged，发生冲突整笔回滚。

数据库地址通过 `POOPSENSE_DATABASE_URL` 配置，应用使用 `postgresql+psycopg://…`。设备及家庭密钥通过隐藏输入或独立的 `POOPSENSE_TEST_DEVICE_KEY` / `POOPSENSE_TEST_HOUSEHOLD_KEY` 环境变量提供，不放在命令行、日志或仓库。二者需不同，禁止公共演示默认密钥。

```text
python backend/scripts/bootstrap_test_workspace.py --household-id hh_hardware_test --owner-user-id u_hardware_test_owner --member-id m_hardware_test_001 --device-id dev_hardware_test_001
```

迁移及一次性登记完成后，测试环境仍保持 `POOPSENSE_APP_ENV=demo`，关闭自动建表及启动种子。使用界面“我的→开发连接设置”连接对应测试家庭。前台接收与初评不依赖worker；若演示自动跟进和通知，需另外启用并验证后台执行。

## 验证与边界

本地发布副本后端493项完整测试、前端157项测试及构建通过；后端包含初始化脚本49项隔离测试。上传定向验证覆盖旧哈希、分类、回执、数据库冲突恢复及迁移。新增 `postgres-demo` CI在独立PostgreSQL17容器中运行全部迁移、测试家庭初始化与权限隔离、上传认领、应用新进程读取，以及两线程同包/异包竞争；检查脚本只接受本机 `poopsense_ci` 库并清理自身随机schema，不接触线上库。

云数据库尚未创建或切换，真实硬件上传到公网、云端重新部署后保存及备份恢复尚未验收。数据库CI、浏览器模拟和现有代码通过都不能替代这些验收。模型仍使用此前切回的DeepSeek；独立本地展会接收端由另一个任务维护，本轮没有将其专用契约混入公网上传接口。
